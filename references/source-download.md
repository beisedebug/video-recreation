# 参考视频下载与导入

统一入口：本地视频／HTTPS 分享链接 → 独立工作目录 → 主视频流与音轨检查 → 完整解码 → 来源清单 → 舞蹈提取或普通复刻。

`scripts/download_reference.py` 封装随包附带的 qiaomu-download 1.3.0 下载实现，普通站点由当前 yt-dlp 提取器解析；视频号走已有本地适配器。它不是各网站永久可用的保证，不自动登录、安装依赖、更新全局工具、开启代理或导入证书。

## 什么时候获取素材

- “下载这个视频”“提取链接中的舞蹈”“复刻这段视频 + 链接”已经给出明确用途，直接获取所需参考，不重复问是否下载。
- 只粘贴链接而意图不明，或链接实际是资料／仓库页面时，不把它当视频下载指令。多链接或播放列表要先确定本次对象与数量；默认不批量下载列表。
- 用户上传的视频优先使用；必要时通过同一入口复制、验证和记录，原文件保持不变。已有成功清单且文件仍可用时复用，不为每次对话重下。
- 只下载或只提取不触发模型选择、付费生成、换角色、发文案或上传素材到生成服务。

## 命令

`SKILL_DIR` 为实际技能目录；`--out-dir` 必须是尚不存在的工作目录，每次尝试一个新版本。

```bash
# 只查本机依赖：不联网、不升级、不安装
python3 "$SKILL_DIR/scripts/download_reference.py" doctor

# 用户已要求下载／分析／复刻这个链接
python3 "$SKILL_DIR/scripts/download_reference.py" acquire 'https://example.com/video' --out-dir work/reference-imports/ref-01

# 本地视频导入，同样完整验证
python3 "$SKILL_DIR/scripts/download_reference.py" acquire '/absolute/path/reference.mp4' --out-dir work/reference-imports/ref-02
```

链接例子只是语法占位，不作为可下载测试素材。默认 `--cookies-from-browser none`、`--wechat-online never`，不读浏览器 Cookie。外部 yt-dlp 读取默认配置和用户缓存的行为已通过内置适配限制；具体补丁见 vendor 中的来源说明。

`--quality best|1080p|720p|480p` 是下载偏好，不是硬分辨率上限；以返回实际规格为准。尺寸过大时保留原文件，另生成分析副本。`--timeout` 控制下载／处理等待，失败不会自动无限重试。凭据不放命令行、不写入提示词和清单。

## 登录与平台差异

对抖音、TikTok、小红书等平台先使用分享链接解析。简短说明将通过链接和下载器获取；若遇登录或验证需用户完成，再继续已授权工作。不继承附件中“抖音一定 403”“必须 dlpanda”的普遍断言。

匿名解析失败时先看错误阶段。若用户已经允许使用指定浏览器登录态，可执行**一次**明确 Cookie 重试，例如：

```bash
python3 "$SKILL_DIR/scripts/download_reference.py" acquire 'https://example.com/video' --out-dir work/reference-imports/ref-03 --cookies-from-browser chrome
```

没有已有授权时才补问是否使用该会话。不能把附件里历史用户同意当本次授权；也不逐镜重复询问已确认的下载策略。Cookie 仅用于目标站点，不发送第三方解析器。登录、验证码和风控页面由用户处理，不自动操作微信或小红书 UI，不换工具规避验证。

微信视频号使用 `weixin.qq.com/sph/...`：

- 已连接后端可用就直接下载，默认只保存一个视频版本。
- `manual_action_required`：请用户手动打开／重新打开该视频并播放；回复后用新目录和 `--wait-page 90` 继续，不再次问是否继续。不要自动操作微信。
- `wechat_setup_required`：说明本机后端缺项，不自动安装或改代理／证书；可请用户提供视频文件。确需首次配置时再读 [上游视频号说明](../vendor/qiaomu-download/references/wechat-video.md)。
- `--wechat-online allowed` 只用于用户已明确允许将这个公开分享 URL 发给第三方解析器的情况。未授权时不自动启用。

Spotify 分享链接不是舞蹈参考视频，本入口会拒绝；需要另行配乐时按用户选择处理，不用匹配到的歌曲冒充原视频。其他站点是否可下载取决于当前提取器、内容和账号权限。DRM、付费墙或访问控制不能绕过；持续失败时保留具体状态并接收本地素材。

## 完成条件与记录

底层下载器返回 `ok:true` 仍需经过包装器验证：返回路径位于本次工作目录内、是普通文件而非越界链接、含实际主视频流、完整视频和音频解码通过且有解码帧。封面图片、纯音频、零长度和损坏文件不能进入后续视频分析。

包装器成功后输出 `files` 中的绝对路径、哈希、实际宽高／帧率／时长、音轨信息和 `full-decode` 状态，以及私有 `manifest.json` 路径。清单记录来源类型、站点 host 和输入 SHA-256，用用户原消息追溯完整链接；不保存 Cookie、签名媒体 URL、完整提取元数据或原始工具错误日志。错误输出保留安全的阶段与下一步建议，不能伪报成功。

清单只是获取与技术验证，构图、身份、舞蹈、运镜和听感保持 `not_checked`，需后续观察。对用户说“已下载”必须有验证过的本地文件；只拿到在线播放页或解析直链不能算完成。

输出目录存于 `work/`，最终成片与用户要求的素材才进入正式交付目录。不要把整个下载工作目录、私人会话数据或后端配置打进技能包／公开视频包。需要公开来源链接时核实它是公开作品页面，不能仅删除 query 就认定签名路径可公开。

## 依赖与上游差异

普通下载需 Python、yt-dlp、FFmpeg 和 ffprobe；本地导入不需 yt-dlp。`doctor` 只报告本地依赖，网络／站点可达性保持未测。缺依赖时报告缺项，按现有环境和授权安装或更新；本分支不自动执行上游 `doctor --upgrade`。

上游代码与 MIT 署名随包保留；其文档只用于追溯和专用适配器说明，实际默认策略以本文件和包装器为准。原生下载器提供更多音频／字幕功能，本融合入口范围限定为参考视频获取，不自动扩大任务。
