# Muse 与 Muse Code 适配

本文件面向执行该技能的智能体。Muse（muse.ai 网页／桌面）和 Muse Code 是不同运行入口；安装命令、可用工具、附件位置及审批方式须分别核实。技能规定制作流程，不能凭文档赋予宿主缺失的能力。

## Muse 网页／桌面：加载完整目录

1. 接收用户提供的技能 ZIP，或读取用户指定的仓库。解压／下载到当前会话可写工作区，保留 `SKILL.md`、`references/`、`scripts/` 的相对结构。不要假定用户 Mac 上的文件可被 Muse 虚拟机访问。
2. 读取 `SKILL.md` 和本文件，按任务读取其他参考。`agents/openai.yaml` 是 Codex 的界面元数据，Muse 无需依赖它。
3. 发现本会话实际可用的文件工具、终端、生图工具、浏览器及附件导出方式。有终端才运行环境检查；没有终端时不要声称已运行脚本。
4. 有原生技能管理入口时遵循其当前说明；没有时将本目录作为当前任务的工作指引。不要捏造网页端安装命令、技能目录或跨会话记忆已保存。只粘贴 `SKILL.md` 不会同时传入其引用文件。

以下可作为用户附上完整技能包时的启动提示词：

> 请加载我附上的 video-recreation 技能包，保留完整目录。先读取 SKILL.md 与 references/muse.md，检查当前会话的文件、终端、生图、视频生成和附件交付能力。有终端时运行 scripts/check_environment.py，报告实际就绪项与缺项。之后按我提供的参考视频执行；生成前分别询问生图模型、动作模型及各自 API 地址／调用渠道，只补问未指定的字段。不要让我在聊天中提供 API Key。完成后导出成片、完整提示词和所用素材。若缺少执行能力，明确尚未完成的步骤，不把读取技能当成制作成功。

## Muse Code：本地技能加载

官方文档提供 `muse skills validate`、`install`、`inspect` 和 `list`。以下命令仅适用于已安装 Muse Code 的终端，目录名以实际解压位置为准：

```bash
muse skills validate ./video-recreation
muse skills install ./video-recreation --scope user
muse skills inspect video-recreation
```

如已从 Codex 个人技能目录自动发现本技能，先检查 `muse skills list`，避免重复安装造成版本歧义。读取和验证不会替用户选择生成模型。版本差异或组织策略可能影响技能发现，实际加载结果优先。

来源：[Muse Code 扩展与技能](https://dev.meta.ai/docs/muse-code/extending)，核对日期 2026-10-16。网页／桌面端不照搬上述命令。

## 生图与动作分开选择

- Muse 内置生图：仅在工具实际存在且用户选择该渠道后使用，遵循工具提供的参考图／编辑参数。未返回版本名时记录“由渠道管理”。保存实际提示词、输入与返回图像。
- 用户选择 Muse Image API：它属于生图阶段。官方当前文档列出 `muse-image-1.0`，基础地址 `https://api.meta.ai/v1`，单次生图／编辑路径 `/images/generations`、`/images/edits`，以及用于多轮编辑的 Responses API。调用前重新核对当前参数，使用宿主已提供或已配置的适配工具。本包没有附带独立的 Muse Image API 客户端。
- 用户选择其他图片服务：保留其选择，使用对应工具；不能因为运行于 Muse 就自动换为 Muse Image。
- 动作视频：单独确认模型与渠道。使用兼容 Grok 异步协议的服务时可复用 `scripts/grok_video.py`；其他服务需它自己的工具／适配器。视频理解、生图和视频生成是三种能力，不能互相替代。

模型说明来源：[Muse Image 接口](https://dev.meta.ai/docs/image-generation)、[Meta 模型目录](https://dev.meta.ai/docs/models)，核对日期 2026-10-16。上面的模型名是可选路径说明，不是默认配置或兼容性承诺。

API 凭据通过当前宿主的安全凭据机制、用户选定的环境变量或已有安全配置提供。脚本只读取指定环境变量；若宿主不允许把凭据提供给脚本，应使用已有授权工具或说明缺项，不提取浏览器登录凭据。

## 媒体处理、续跑与交付

在已确认的任务工作目录创建 `work/` 和 `outputs/`；尊重宿主已有目录约定。将附件解析为真实本地路径，再运行 [数据与命令](schema.md) 中的媒体命令。Python 3.9+、FFmpeg（含 libx264，带音轨合成还需 AAC）是本地脚本路径的依赖；联系表需 Pillow。缺依赖时按宿主许可安装，或保留可完成的分析并报告缺项。

外部生成的状态文件、请求 ID 和素材必须保存到持久工作目录；恢复时查询原任务，不重复提交。内置工具未提供任务查询接口时，只记录它实际返回的回执，不能伪造查询能力。终端调用限时不等于生成任务失败。

MP4、提示词和素材 ZIP 通过当前会话的附件／产物工具导出，并验证用户可打开。不能把虚拟机的 `/tmp/...` 或其他内部路径当成下载链接，也不能为了交付自动公开发布文件。

## 验证层级

每个环境分别记录以下项目，不把其中一项通过当成全部通过：

1. **加载与依赖：** 已读取完整目录；本地依赖和宿主工具是否可用。
2. **离线媒体链路：** 测试片段可探测、抽帧、重剪、完整解码，并符合目标帧数和音轨要求。
3. **真实生成链路：** 用户确认模型和渠道后，典型短镜头的生图、动作、查询与下载是否跑通。
4. **用户交付：** 实际附件能预览和下载；视觉／动作质量另按主技能验收。

未在 Muse 会话实测的项目写 `not_checked`。本地通过 Python／FFmpeg 测试不等于通过 Muse 的工具调用、登录、付费接口或附件交付测试。
