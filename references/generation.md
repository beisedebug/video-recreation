# 生成路径、权限和任务续跑

## 生成前分别确认两条路径

本技能把生图、动作视频和本地剪辑分开。每个需要生成的新任务，先询问用户本次使用的模型与渠道。可在一次交互中列出两项，避免逐字段来回询问；有异步提问工具时一并提交两个问题，没有该工具时在对话中询问：

1. **生图：** 本次使用哪个生图模型？请同时指定 API 基础地址（base URL）或调用渠道，例如当前平台的内置生图、某个已配置提供商、网页工具。
2. **动作：** 本次使用哪个动作／视频模型？请同时指定它的 API 基础地址或调用渠道。两者可以使用不同服务。

- 本次请求已指定的字段直接记录，只补问缺失项；仅生成动作时不追问生图配置。只要提示词、分析或编辑现有素材时不强制选择生成模型。
- 可以把已知历史组合列为“沿用上次”的选项，同时写明两种模型和各自渠道。用户明确选择沿用后即可使用已有配置，不要求重新输入地址；不能因为过去成功过或配置中存在 key 就自行选定。
- 内置工具或网页渠道不要求 API 地址；若渠道不开放模型选择，记录用户选择的渠道及“由渠道管理”，不要编造具体模型版本。单独说“使用 image_gen”不等于选择第三方 API。
- 等待回答时继续探测视频、抽帧、拆镜和编写通用提示词。缺少必要选择时，不向未确认的服务上传素材或提交生成；没有回复不视为确认。
- 将选择记录在任务中，格式见 [数据与命令](schema.md#生成配置记录)。同一任务的批量生成、修正和续跑沿用已确认配置，不重复询问。更换模型或渠道、启用替代服务时先确认变更；一般的直接执行授权不代替模型选择。

## 按选择检查实际能力

检查当前可调用工具以及用户确认的路径，不能把“工具名不在列表”当成所有能力均不可用。所选路径不可用时说明具体缺项和可行选项，不静默切换模型或服务。

按宿主选择调用方法：

- **Codex：** 使用可用的 `imagegen` 技能时读取其当前指引。用户选择内置生图时使用内置 `image_gen`；选择或确认该技能支持的 API/CLI/模型路径时，使用其原装 `scripts/image_gen.py`，不要改该脚本或另写图片 SDK 调用器。
- **Muse 网页／桌面：** 发现会话实际提供的生图工具并读取说明；用户选择该渠道后，提交完整提示词和参考图。工具未暴露模型版本时记录“由渠道管理”。不要尝试调用 Codex 私有工具或查找另一台机器的配置。
- **Muse Code 或其他宿主：** 使用当前已提供、已获授权且适配所选模型的工具／CLI。发现了 `SKILL.md` 不代表同时安装了生图工具或模型服务。
- **用户指定外部服务：** 核对其真实接口和参考图能力。现有 Grok 脚本只负责对应视频接口，不能作为通用生图或其他视频模型适配器。Muse Image 是可选的生图服务，详见 [Muse 适配](muse.md)。

2026-10-12 至 14 的成功案例使用过 GPT Image 2 生成静态图、Grok Imagine Video 1.5 生成动作。这只是历史组合，不是默认选择或固定依赖。提交前核对用户选定模型在该渠道支持的分辨率、时长、首尾帧／关键帧及其参数组合；不能仅凭模型名称推断接口兼容性。

选择完成后，只就确实缺少的登录、凭据、路径／网络权限或替代服务选择补充沟通。API 地址与 API key 是两件事：凭据从已有安全配置或环境变量读取，禁止回显到消息、提示词、日志和交付包；缺凭据时让用户在安全配置处设置，不要求把完整 key 粘贴进聊天。读取配置应限定到选中的提供商，避免倾倒整个配置。

操作授权与沙箱权限是两回事。需要额外目录／网络权限时使用当前宿主实际提供的授权机制；Codex 中可能是 `request_permissions`，Muse 中遵循其会话工具和审批界面。解释具体缺项，不让用户重复审批每张关键帧，也不承诺跳过宿主要求的审批。不得通过改全局权限设置、另建账户或外部发布绕开限制。

## Grok 异步辅助脚本

`scripts/grok_video.py` 适配已验证的 `/videos/generations` 提交与 `/videos/{id}` 查询接口。它不是通用所有服务适配器。显式提供 `base_url`，不内置任何私人网关。读取 `VIDEO_API_KEY`，使用现有已授权的提供商即可；该环境变量名可通过 `--key-env` 改变。

请求支持 `model`、`prompt_file`、`duration`、`resolution`、`aspect_ratio`、可选 `image`、`last_frame` 和 `keyframes`。图片作为原始图像文件的 data URL 发送；需要压缩时先另存输入副本，并将副本列入记录。参考模型支持与限制时查阅当前官方文档，不从历史成功请求推导所有参数都能任意组合：

- [视频生成](https://docs.x.ai/developers/model-capabilities/video/generation)
- [图生视频与参考帧入口](https://docs.x.ai/developers/model-capabilities/video/image-to-video)

首尾帧/关键帧是参考控制，不是保证每一帧完全遵循。核心动作仍须看输出。

## 可恢复状态

每个生成版本独占一个状态文件，绑定完整提示词、图片内容摘要、参数和提供商地址。保存 `request.json`（无凭据）、回执 ID、阶段、错误类别、输出路径。已知 ID 后只查询它，不重新提交。

POST 前先持久化 `submit_uncertain`。若连接断开、超时、服务端错误或回执无法解析，任务可能已计费受理；保持不确定状态，查服务端记录或沟通，禁止自动重复 POST。脚本在同一状态文件上会阻止再次提交。明确拒绝或明确 `failed` 后，分析原因并用新的版本/状态文件重试；不能删除旧记录假装首次生成。

查询每次只进行一次网络请求，按服务预计时长安排下一次检查。限流/网络查询失败可稍后重试查询；不得变成重提生成。下载失败继续下载已有任务结果。超过当前模型合理等待时长就检查状态原因，不无限忙轮询。并发数依据服务限制和费用预算设定，历史案例的 4 路并发不是通用默认值。

对图片与视频都保存最终实际使用的输入和输出。记录请求尺寸与返回尺寸的差异；服务标称 1080p 不一定返回 1920×1080，合成前检查实际媒体。输出 URL 可能过期，成功后及时保存到任务素材目录。下载媒体时不向结果 URL 附带 API Authorization。

## 错误分流

- HTTP 413：先压缩/缩放参考输入副本，保持所需纹理和构图，再开新版本；不要修改原始参考。
- HTTP 401/403：确认所选提供商和凭据权限；不扫描或试用无关账户。
- HTTP 429：遵守重试时间；对未明确拒绝的 POST 保留不确定状态。
- 已确认任务失败：有限次数重试；持续内容或服务失败后报告实际原因。
- 身份或构图错：修图片参考/提示词，再做动作。
- 首尾对、中间错：修阶段控制、锚点和运动主体，不能仅反复增加“电影级、丝滑”。

新环境使用前运行本地准备与脚本帮助；真正调用生成服务只在当前任务需要且已获授权时进行。创建/测试本技能本身不需要付费生成。
