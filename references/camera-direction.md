# 运镜选择与对话

用于参考视频复刻和指定镜头重做。目标是把用户的想法变成能制作、能验收的镜头计划。没有参考视频时先接收参考或仅整理构思，不捏造已观察到的镜头。

## 1. 一次说明两种入口

用户尚未说明创意倾向时，可问：

> 这次运镜希望沿用原片、只改几个镜头，还是按你的想法重新设计？你可以直接选“慢慢推近、拉远揭示环境、侧面跟拍、绕人物拍、升高俯看、手持记录”等，也可以直接描述想看到的效果。

有交互选择工具就用实际可用的工具；没有就用简短编号菜单。不要假装创建了界面按钮。把已经明确的内容作为答案：用户说“固定镜头，只让人物转身”便不再问是否环绕。不要强迫用户先选技术术语或模型。

| 创意模式 | 含义 | 默认保留 |
|---|---|---|
| `faithful` 沿用原片 | 先分析并复现原运镜 | 参考中的人物、动作、构图、节奏，除非另有要求 |
| `customize` 局部改 | 仅修改指定镜头或区间 | 未授权区域，以及改动区间内仍被指定保留的内容 |
| `remix` 按想法重设计 | 允许重新编排运镜 | 用户明确要求保留的人物、故事、风格或其他约束 |

若用户只说“复刻”且可选问题未回复，可继续按沿用原片做分析和草案；不要据此加入新创意。提交生成仍依已确认的生成配置与任务授权。选项没有被用户提交不算选择。

## 2. 直接选运镜

先展示适合当前参考和目标的 3–6 个选项，可包含“沿用原运镜”；用户想浏览更多时再列全部。用人话效果加技术名称，例如“慢慢靠近人物，看清表情（推近）”，不必让用户填写每个摄影参数。

```bash
python3 "$SKILL_DIR/scripts/camera_library.py" list
python3 "$SKILL_DIR/scripts/camera_library.py" search "绕人物"
python3 "$SKILL_DIR/scripts/camera_library.py" show orbit
python3 "$SKILL_DIR/scripts/camera_library.py" examples "手持"
```

`camera-presets.json` 是原创运镜卡；`seedance-index.json` 是源库的案例元数据索引。用户可直接给卡片 ID，或把几个动作按时间组合。命中不代表适合当前视频，零命中也不表示无法制作。

## 3. 用对话理解想法

参考为舞蹈时，用 [舞蹈分析](dance-analysis.md) 的尺度、横移、竖移、可见面、地平线与焦点六项证据检查原运镜。各项允许“不确定”；人物转身、数字裁切和相机环绕分别判断。用户要求改变相机时，新运镜计划覆盖对应参考要求，人物动作是否保留仍单独记录。

由智能体读取用户原话、上下文和参考画面，保留否定、顺序、范围和后续纠正。关键词脚本不能负责自然语言理解，也不能依据“不要环绕”中的“环绕”决定采用环绕。

| 用户表达 | 可转成的候选意图 | 需要留意 |
|---|---|---|
| “先看全身，慢慢靠近看脸” | 推近，景别从全身到近景 | 用户只强调画面放大时，区分机位推进与原地变焦 |
| “人继续往前走，镜头一直跟着” | 跟拍 | 正面后退跟拍、侧面跟拍、背后跟拍会改变结果；参考能确定就沿用 |
| “绕她半圈，最后看到背影” | 相机环绕约 180° | 人物转身与相机绕行不同；不要把顺时针写死，方向影响结果时补问 |
| “人别动，拍出周围空间” | 固定主体，拉远或环绕 | 给两个具体候选效果，未选前不自行锁定 |
| “压迫一点” | 可候选缓慢推进、低机位等 | 情绪不是唯一镜头指令，先给建议而非宣称用户已选 |
| “相机别动，人转一圈” | 固定相机 + 人物旋转 | 明确保留相机位置、朝向、焦距；不采用环绕 |
| “不要绕了，只在最后两秒拉远” | 覆盖旧方案；仅尾段拉远 | 更新允许修改区间，撤销冲突的旧提示词 |

缺失细节不影响结果时按参考和已有要求补全，并标为推断；只有会产生明显不同成片的歧义才问一个具体问题。不能把自行补充的精确焦距、角度、速度写成用户原话。

以下要分别描述：

- **相机运动：** 推拉是机位移动；横移是机位侧移；摇摄是原地转向；升降是机位高度改变。
- **主体运动：** 人走、转身、抬手，不等于摄影机移动。
- **焦距／焦点：** zoom 是变焦，rack focus 是焦点转移；都不自动表示机位移动。
- **静态视角与剪辑：** 俯拍、微距是视角／景别；一镜到底和蒙太奇是镜头组织。甩镜本身不必有切镜；有转场时另记切点。

## 4. 展示简短镜头计划

将用户输入转换为一段可审阅的话，后接必要镜头表：

> 按你的想法，第 2 镜前半段保留全身构图，后半段相机从正面缓慢靠近，到胸像结束；人物继续原来的动作。其余镜头和音乐沿用原片。

这段说明用于让用户看懂执行内容，不额外制造逐镜审批。已经明确且不存在冲突即可继续；必须澄清的歧义保持待定，不能用等待超时当作认可。

在 `work/camera-plan.json` 记录，或在现有项目记录中引用同等信息。此文件是智能体工作记录，媒体脚本不会自动执行它：

```json
{
  "creative_mode": "customize",
  "input_mode": "conversation",
  "user_intent": "只在第2镜最后两秒慢慢靠近，人继续原动作",
  "fps": "24",
  "shots": [{
    "id": "shot-02",
    "source_range_frames": [96, 192],
    "output_range_frames": [96, 192],
    "editable_output_ranges": [[144, 192]],
    "protected_output_ranges": [[96, 144]],
    "reference_observation": "此例假设：原片为固定全身镜头；实际任务必须观察后填写",
    "reference_status": "example_only",
    "camera_phases": [{
      "output_range_frames": [144, 192],
      "preset_id": "push_in",
      "path": "从正面向主体靠近",
      "framing_start": "全身",
      "framing_end": "胸像（工作假设）",
      "speed": "缓慢、平稳",
      "subject_motion": "沿用原片",
      "cut": "无切镜"
    }],
    "preserve": ["身份", "服装", "场景", "原动作", "原音乐"],
    "unresolved": [],
    "assumptions": ["结束胸像构图为工作假设，非用户明确指定"],
    "decision_basis": "用户已明确要求局部推近",
    "model_check": "not_checked"
  }]
}
```

帧区间一律左闭右开；图中数字仅演示结构。实际边界从源视频和目标 fps 累计换算，并列全全部保留区间。对 VFR 源另外存 PTS 映射。复刻模式与创意模式分别记录，不改变现有 `project.json` 的 `recreate / transition / reedit` 定义。

**同时换角色和改运镜时，按维度记录范围。** 例如“全片换成我的角色，只有尾部两秒改成拉远，动作和音乐保留”：身份在全片可改，相机仅尾部可改，动作与音轨全片保留。可在计划中增加 `dimension_scopes`，逐项写 `dimension`、`editable_ranges`、`preserved_ranges` 与 `validation_method`。此时前段的“相机保留”不等于整张画面像素不变；身份变化需要生成的区间按角色与动作语义验收，真正未修改的原素材区间才使用逐帧／像素对照。

## 5. 转成各渠道的生成输入

先写模型无关的镜头说明：起始构图 → 人物动作 → 相机分阶段运动 → 结束构图 → 保留内容 → 切镜／音轨约束。再依据 [平台与模型选择](model-selection.md) 和实际工具参数编译请求。

- 支持参考视频时，说明视频用于动作／运镜／节奏中的哪一项。若用户改了运镜，明确文字要求覆盖参考的运镜；若工具无法解耦，就提取关键帧并使用新方案，不能同时要求“完全复制运镜”和“使用相反运镜”。
- 只支持首帧时，用首帧约束身份和构图，文字描述运动。首帧不能保证精确轨迹；需要首尾帧／参考视频而渠道不支持时，先说明可行替代并由用户选择影响范围较大的改法。
- 原片只改尾部时，优先生成并拼接被授权的区间；整段视频编辑不保证其他帧不变。不能为了改运镜静默重生成整片。
- 复杂组合先按阶段排序。不要把相机前进、后退、环绕同时塞进同一时间段，也不要把多个服务的专用参数原样混用。
- 案例里的“4K、30 秒、360°”是作者请求文本，不证明接口真的提供这些规格。提示词范例和官方参数分别核实。

## 7. 验收

对照修改后的镜头计划检查相机方向、机位／焦距变化、主体是否误转、结束构图、切点和运动节奏；对照原片检查必须保留的内容。分别记录 `pass / fail / not_checked`。技术解码通过不等于运镜符合。若平台不能达到核心目标，说明偏差，并只重做失败区间或提出有明确取舍的替代方案。
